# UI 原型状态画布

## 适用范围

- 将已有 HTML 原型接入浏览器评审画布，保留原有页面、素材和交互。
- 按业务流程、用户类型和页面名称组织原型；支持顶层 Tab 和子分组。
- 在同一目录下平铺展示同名页面的不同状态，提供目录定位、平移缩放、元素检查、复制定位信息和独立查看原型。
- 新建原型时按用户要求确定内容、风格和尺寸；处理已有原型时，以源文件为准。

用户当前明确要求优先。对已有原型，本规则覆盖模板或旧说明中的统一固定视口、默认适应画布、逐状态重复目录、目录点击只展示单张同名原型等做法。

## 执行步骤

### 1. 读取和核对源文件

先确定项目根目录，在其下建立本次任务的独立工作区；后续迭代沿用该目录。将画布置于工作区的 `board/`，本次新建的原型、设计稿、数据和素材集中在同一工作区。复用已有前端时使用原项目路由或相对路径。

读取源 HTML、样式、脚本、素材及相关需求，不仅凭文件名或截图推测结构。逐张记录：

- 稳定页面标识、源路径或路由及原有顺序。
- 原型自身左上角名称原文，和每张原型外部自带的备注（包括右上角说明）。
- 原有宽高、完整内容高度、长页和原生滚动区域。
- 用户类型、业务分组、状态、弹窗、按钮和跳转关系。
- 内容属于真实 HTML 还是参考图片。

名称与备注可能在手机页面容器外；接入时必须同时读取并保留，不能只取 `.app` 而丢掉页外说明。缺少关键名称或尺寸时先核查源文件；仍无法确定再询问，不自行编造。

### 2. 建立目录与分组

- 左侧目录使用原型自身左上角名称的原文；不缩写、不重命名，不擅自删编号或添加括号、状态后缀。
- 在同一业务/用户分组内，将左上角名称完全相同的原型合并为一个目录项。仅忽略排版造成的首尾空白，不按语义擅自合并不同名称。
- 点击该目录项时，展示其下全部相关原型，按原顺序平铺；不得重复生成同名目录项、遗漏同名页面或只展示其中一张。
- 不跨用户分组混合页面。保留用户指定的顶层 Tab、子分组及顺序。
- 同一目录内用稳定状态标识区分各张原型和元素定位，不依赖显示名称作为唯一键；将独有备注继续放在各自页面外。

### 3. 沿用原尺寸平铺

- 在源文件预期的展示环境中核对各张原型的宽高，以原有尺寸建立画布；不同页面允许不同尺寸。
- 不统一套用 390 × 844 或其他手机画框，不拉伸、压缩、裁切，不改字号、布局或素材来凑齐尺寸。
- 将长页面按原有完整高度展开；不得新加固定高度或内部滚动窗来截断整张原型。保留源文件本来就有的局部滚动交互。
- 按分组和原有顺序平铺，保留必要间距。保留原文件自带的视觉设计，但不额外加手机壳、边框、阴影外框或装饰。
- 在对应页面外完整呈现原名称和备注；测量尺寸时将这些说明的空间计入，避免遮挡或截断。
- 新页面才按用户指定设备和尺寸设计；仅当全新手机页面确实未指定尺寸时可采用 390 × 844，不能套用到已有原型。

### 4. 复用页面与接入画布

将 [画布模板](assets/canvas/index.html) 及其资源复制到工作区 `board/`，编辑副本的 [配置](assets/canvas/board.json)。模板是起点，不是验收完成品：其中固定宽高、逐状态目录、加载时自动适应画布等默认行为必须按本规则适配。

- 在 `groups` 与 `states` 中映射原有页面/状态入口；必要时扩展目录映射与每页尺寸字段，不为兼容旧配置而强改页面尺寸。
- 按实测尺寸为每页建立独立容器。若使用 iframe，通过同源测量、尺寸消息或预先测得的尺寸保持原页面大小；加载占位尺寸不能作为最终固定尺寸。
- 画布与页面在同一站点提供服务以支持元素检查；单文件交付可内嵌同源 `srcdoc`。复用原页面组件、样式、素材和渲染逻辑，状态通过参数或预置数据展示。
- 保留按钮、表单、选中状态、弹窗、返回及页面跳转，不用空点击处理器或“已打开”提示冒充实际操作结果。
- 从根元素到最深层节点（含文字容器、图标、SVG 子元素与装饰）设置实际、稳定、唯一的 ID；保留已有有效 ID，避免破坏脚本引用。动态列表按稳定条目标识分配 ID。
- 用“业务分组 + 原名称 + 稳定状态标识 + 元素 ID”定位，复制后应能准确找到同名原型中的具体元素。
- 每张原型隔离演示状态，操作一张时不得意外改变其他原型。
- 将 `prototypeSrc` 接入项目真正可独立操作的原型入口。验证打开、返回、再次打开；不能只生成可能被拦截的 Blob/弹窗链接。受交付环境限制时提供经过验证的当前页独立视图或可下载原型，并说明行为。
- 图像仅作参考时如实标明。不得把可交互 HTML 改为整页截图加透明热区；图片内控件不得冒充真实交互，需要重建时另按用户要求实现。

### 5. 保持清晰与100%默认显示

- 默认打开为100%，不调用自动缩小整张画布的适应操作；目录定位不得悄悄缩放。
- 用户主动缩放只改变查看比例，不改写源尺寸、字号和布局。回到100%后恢复清晰。
- 平移保持当前比例，坐标对齐实际像素，处理拖拽结束、指针取消及滚轮平移结束后的定位。
- 在100%下优先避免对整块巨大页面集合叠加平移/缩放合成；可用布局定位或其他经验证的清晰方案。使用 transform 时必须实测，不以特定 CSS 属性作为清晰度保证。
- 不使用低清截图或持续低分辨率缓存替代真实页面；不盲目增加 `translate3d`、`will-change` 等而跳过验证。
- 分别核验默认显示、连续平移、松手、目录定位、缩放后回到100%的文字及控件清晰度；点击目录前后不能出现明显清晰度差异。
- 源素材本来低清时说明其限制，不将其宣称为高清，不未经授权更换或重绘。

### 6. 验收与交付

在真实浏览器中验证交付文件的实际打开方式（HTTP服务、离线HTML或目标容器），不得只用静态代码检查、DOM模拟器或配置数字代替视觉验收。

逐项检查：

1. 默认100%；源尺寸和长页完整；原名称、右上角及其他页外备注均保留；无新增外框。
2. 目录名称与源文件逐字一致；同名页面归入一个目录；点击后显示该组全部页面，数量和顺序正确；顶层 Tab 与子分组不混淆。
3. 默认、平移中、平移后、目录定位及回到100%均清晰；平移不改变比例。
4. 画布所有按钮、Tab、目录、模式切换、缩放复位、复制定位信息、独立原型打开/返回均有实际效果。
5. 原型已有按钮、表单、弹窗、返回和跳转可操作；参考图片的交互限制如实标示。
6. 实测每页尺寸；检查缺失/重复 ID，点选最深层节点，确认复制信息能区分同名状态；验证状态隔离及代码复用。

发现模糊、缺页、备注丢失、尺寸变化或按钮失效时，先修复再交付完成版。浏览器不可用或视觉检查未完成时，可保存待验收版本，但必须明确未通过的项目；不得声称“确保不糊”“清晰度已验证”或“全部功能通过”。

## 输出规范

| 项目 | 必须遵守 |
| --- | --- |
| 默认查看比例 | 100%，不自动缩小 |
| 页面尺寸 | 各张原型原有尺寸，长页完整展开 |
| 排列 | 按业务分组、同名目录及源顺序平铺 |
| 左侧目录 | 原型自身左上角名称原文，同名合并 |
| 页外名称和备注 | 完整保留，与对应原型绑定 |
| 外框 | 不额外添加，不擅自改变源设计 |
| 清晰度 | 实测默认、平移、定位、缩放复位后的表现 |
| 交互 | 所有画布按钮与已有原型交互正常可用 |
| 交付 | 可打开画布、完整源码及依赖素材；说明改动、验证与限制 |

提供用户可打开的入口、工作区位置和必要启动方式。遵循当前环境的持久保存机制；Skill 本身通过技能目录保存，不当作普通原型文件存储。

现有前端使用原项目开发服务器。纯静态多文件项目在项目根目录从1104检查端口，依次递增到首个空闲端口；启动命令与交付地址必须使用同一个实际端口，例如：

```sh
python3 -m http.server 1104 --bind 127.0.0.1
```

## 注意事项

- 不擅自增改文案、业务功能、状态、尺寸、布局、字号、颜色或素材。
- 不丢弃页外标题与备注，不用统一默认手机视口替代源尺寸。
- 不依赖同名目录区分状态，使用稳定标识，不漏页、不重复目录。
- 保留原发布地址作为明确约束；用户未授权时不覆盖线上、不新建分享链接替代。生成文件、更新 Git 和 WorkBuddy 发布分别验证，不能声称会自动互相同步。
- 用户明确要求改变目录聚焦、外框或尺寸时遵从该次要求；不要把历史项目的特殊实现当成所有项目的默认规则。

## 新建页面的可选视觉流程

仅在任务需要新设计时列出主流程及必要异常分支，参考原项目品牌变量、反馈页样式和用户指定风格。可先生成主屏设计稿，再以它为参考生成其他状态，统一已确认的新页面视口；用共用组件实现，仅改变状态差异。弹层保留原页面背景，演示数据前后一致。

复杂装饰先用代码还原，最多对照渲染尝试三轮；仍有明显差距时可将该处单独生成 PNG，需要透底则用透明背景。文字、按钮和布局继续使用真实 HTML/CSS。不得因此更换或修改用户提供的已有设计。

# HTML 原型标注工具

## 目标

把 HTML 原型和标注清单转换为一个可直接预览的已标注副本。标注必须是静态内嵌数据和脚本，避免依赖 Library 预览区的文件句柄、跨域访问或浏览器扩展。

## 工作规则

1. 先确认输入 HTML、标注范围和输出文件名；源文件只读，始终输出新副本。
2. 若用户没有提供具体标注内容，先从页面真实结构、现有交互代码和用户明确要求整理标注清单；不凭空增加文案、功能或业务规则。
3. 清单固定包含：编号、菜单路径、目标区域、注记类型、注记内容。技术定位信息放在 HTML 内部，不放进简洁清单。
4. 每条注记使用稳定 `id`，定位优先级为 `data-*`/唯一 id > 稳定 CSS 选择器 > DOM 路径和文字指纹。无法唯一定位时标记为“待人工选择”，禁止挂到相似元素。
5. 注入时保留原始 HTML 和原业务脚本；运行时只添加独立的 `hae-gpt` 标注层，不改写按钮行为。
6. 交互采用“点击标记查看、点击添加后选中元素、表单确认立即更新、导出生成新文件”的单向流程。不要使用“确认选区”中间步骤，不调用文件选择器，不把浏览器缓存当成已保存文件。
7. 在 GPT 预览环境中，保存按钮只生成可下载的新 HTML 和 Markdown 清单；如果环境支持本地文件，则另行提示用户下载后在 Chrome/Edge 打开。

## 输出

- `<原文件名>-已标注.html`
- `<原文件名>-注记清单.md`

HTML 内嵌 `window.__HAE_GPT__`，包含 `notes`、`sourceFile`、`version` 和定位信息。注记类型仅允许：`字段说明`、`交互逻辑`、`业务规则`、`修改原型`。

## 处理已有标注文件

先读取 `window.__HAE_GPT__`；保留稳定 id、编号顺序和正文。编辑、删除或新增后重新编号，保存为新版本，不覆盖用户源文件。若旧文件只有 `hae-data`，读取后转换为本技能的数据结构。

## 验证

运行 `python3 <skill目录>/scripts/annotate_html.py --check <文件>`，检查：脚本存在、数据可解析、编号连续、id 唯一、每个定位器最多命中一个目标。无法在真实浏览器中验证时，明确说明仅完成静态验证。

## 交付说明

告诉用户输出文件、注记数量、未匹配目标和验证范围。不要声称已经写回原文件；只说明已生成新的已标注副本。
